# 行为回归测试

## 标准提示词

> 先建立可重复的基准场景，用回放做行为回归，用前后基准测试验收性能。对能确定性重现的状态，在关键帧做校验。

## 流程与验收

1. **约定怎样算通过。** 改动前写明要保持的可观察行为、检查点、允许的差异，以及用户关心的性能指标和最低收益。沿用项目已有目标；缺少目标时把探索性测量和达标结论分开。
2. **建立基线。** 用代表性输入复现问题，重复运行旧版，记录行为和性能波动。随机行为可固定种子或记录事件；仍会波动的结果按预定业务规则或统计范围检查。
3. **定位热点并做最小改动。** 采样找出耗时来源，提出一个可检验的假设，说明这项改动预期改善哪个指标。
4. **回放验行为。** 用同一输入重跑新版。确定性状态在约定检查点应与基线一致，可直接比较字段或哈希。出现未约定的差异时，缩小到首次分歧的区间，定位并修正后再回放。
5. **前后对照验性能。** 行为通过后，在同一环境和负载下重复比较新旧版。用户指标达到事先约定的目标，且收益能与基线波动区分，才算性能通过。未达标则记录结果，停止该尝试或重选假设；数据不足则标为待验证。
6. **集成回归。** 两项通过后，在集成版本复跑受影响的关键路径，记录通过范围和遗留项。

**收益**：同一段回放可同时检验行为是否偏离、优化是否改善实际指标。关键帧的差异能缩小排查范围。

**成本**：需要准备和维护基准、重复运行以估计波动。可将相关修改合并验收，发现分歧时再加密检查点。
