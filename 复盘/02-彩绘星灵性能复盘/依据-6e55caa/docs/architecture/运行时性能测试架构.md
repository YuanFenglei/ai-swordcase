# 正式版运行时性能测试架构

玩家反馈游玩到第三关逐步变卡。要回答两个可分别验证的问题：从哪一次节点战或换图开始，哪段工作占用了慢帧时间？这一段的负载增长，有多少来自当前玩法，有多少来自本应随上一关退出的资源？目前缺少同一自然局贯穿三关的数据，根因待测。下述采集器、报告及验收是待实现方案。

## 主样本怎样抵达第三关

| 样本 | 输入与观测范围 |
| --- | --- |
| 自然长局（复现依据） | 从正式菜单开新局，同一进程、同一局、正常倍速，由引擎调度物理与显示。真人操作或仅回放玩家能做的移动、技能、奖励和出发输入，分别标明来源。保留自然刷怪、染色、拾取、成长和死亡。记录开局种子及输入时序；操作驱动只读里程碑核对进度，不改规则状态。 |
| 固定负载（定位对照） | 保留现有 GM 场景和六伙伴基准，按相似队伍、敌人数、画面设置复测单个热点。现有基准直接写入六伙伴、高血量敌人和保护，手动推进 600 步，前 60 帧预热；历史 300 模拟秒样本也是加速夹具。它们只承担专项回归。[当前基准](../../src/game/full_game/performance_test.gd) · [历史长时样本](../reviews/性能分析/石碑染色与长时性能验证_2026-11-17.md) |
| 同场景重复进出（回收对照） | 同进程内用相同种子、路线和选择重复开局，待共享资产预热后，在相同位置、镜头、阶段和队伍规模比较。另起进程取得冷启动基线。专项夹具可控制负载，报告单列。 |

自然长局在前两颗星球各实际靠近并完成至少三个不同小节点，打守卫、看完区域还原、处理奖励和成长、击败 Boss，再经正常出发入口换图。第三颗星球继续移动、战斗和留色，至少覆盖其第三个不同小节点及其后的恢复探索窗口。按星球号、本星球节点完成序号、节点 ID 和阶段分桶，第一颗星球上的第三个节点也能单独检索。死亡、超时、路线分叉或遗漏里程碑时保存已采数据和中断原因；只有实际完成的区间参与比较。[路线与奖励](../design/游戏与流程/单局路线与奖励.md) · [星球准备和出发](../../src/game/full_game/level_system.gd)

从开局首帧开始记录。给每次入场、交战、还原、决策面板、Boss 击败、换图前末帧、新图首帧及稳定探索打标。保留玩家标注“开始卡”的时刻。初次加载、换图和等待选择各自汇总；连续探索战斗另算。记录真实经过时间与模拟时间，前后台、暂停、失焦和采样缺口显式标记。

## 每一帧怎样归因

显式开启运行时采集，沿用正式场景与引擎时钟；现有启动计时在封面结束。场景层负责帧号、物理步号、阶段和生命周期，系统在原有工作边界累计计时与数量，采集器只接收标量。离线汇总按同一局和时间窗关联帧、资源样本与事件。已有 GM 单点读数和专项窗口 GPU 计时可以复用。[启动计时边界](../production/性能分析/GM与启动计时.md) · [GM 指标](../../src/game/full_game/gm_commands.gd) · [主场景时序](主游戏代码架构.md)

| 范围 | CPU 侧计时位置与同步记录 |
| --- | --- |
| 整帧 | 连续绘制回调间以单调墙钟计时，输出毫秒。记录区间内实际执行的全部物理步、显示回调及同步次数，保留零步和多步帧。主线程未覆盖区间单列，结合限帧、垂直同步和等待分析。 |
| 逻辑计算 | 在世界推进入口拆移动、刷怪与敌方 AI、伙伴索敌与攻击、笔触接触与地伤、节点与奖励。同步记敌人及队伍数、在途攻击、接触/候选次数、活跃地伤格和总留色格，区别调用变多与单次变慢。[世界推进](../../src/game/full_game/game_world.gd) |
| 特效 | 拆飞行球/笔触生成、飞溅创建与逐次更新、回收，记录实例数及本帧处理数。规则侧的命中与显示侧的飞溅分开；持久地色随纹理统计。[特效分派](../../src/game/full_game/brush_fx.gd) · [接触飞溅](../../src/game/full_game/brush_impact_fx.gd) |
| 模型与角色显示 | 拆换图静态构建、角色实例创建/释放、姿态动画、贴纸对齐与可见性更新。区分石碑、地物等网格与角色 Sprite3D，关联可见数及本帧更新数。[世界显示](../../src/game/full_game/world.gd) |
| 贴图 | 在真实加载/首次构建、缓存查询与未命中、CPU 改写图像、创建/更新纹理的提交调用分别计时。区分共享角色/特效图集、动态身体染色、地表控制页和笔触表，记录脏页、上传次数及字节。[地表控制页](../../src/game/full_game/ground_paint_pages.gd) · [笔触表](../../src/game/full_game/ground_stroke_table.gd) |
| 渲染与其他主线程工作 | 拆显示快照采集、世界同步、HUD/边缘提示和渲染提交。角色同步位于物理回调，世界刷新还受 0.08 秒节流，按实际调用记账。另取 viewport CPU/GPU 时间、draw calls、绘制对象和图元数，标明后端与有效性。[物理及显示回调](../../src/game/full_game/main.gd) · [快照缓存](../../src/game/full_game/display_snapshot_cache.gd) |

每个 CPU 区间保存调用数、包含时间及扣除直接子区间后的自身时间。按线程分别统计；墙钟包含调用中的等待。GPU 与 CPU 可并行，纹理提交返回只表明 CPU 完成该调用。GPU 数值记录来源帧（若可知）、读取帧与延迟；后端缺测、零值无效或无法对齐时标明原因，按有效窗口比较。整帧 GPU 时间不能细分为特效、模型、贴图各自的绘制时间；需要进一步归因时，用同路线同负载的单项显示开关对照，或采目标后端支持的 GPU 分段捕获。CPU、GPU、父子区间各有口径，不相加为总帧耗。

## 数量怎样反映生命周期

每类记录所有者（全局共享、整局、星球代次、临时效果）、子类、期初/当前/峰值、新建、实际释放、复用、待释放。池内空闲和借出分别计数；归还只改变池状态。按实例 ID 或资源 ID 去重，记录代次以防重用。共用贴图的多个节点算多个使用者、一份底层资源；跨类引用只作关联。计数器由创建、借还、替换与最终释放事件驱动，采集器只存 ID 或弱引用，避免探针自身留住对象。

| 类别 | 计数单位与交叉核验 |
| --- | --- |
| 特效 | 区分在途规则实例、实际显示节点/批次、当前活跃与池内空闲，按飞行、命中、飞溅分组。检查发射停止、效果寿命到期后的回落。 |
| 模型 | 分别记存活的静态/动态显示实例、树内可见实例、唯一 Mesh 与材质、材质登记表长度。可见标记与引擎实际绘制数分别留档；隐藏、出树、排队销毁、最终释放是不同事件。 |
| 贴图 | 区分唯一底层纹理、图集区域/使用者、CPU Image 页、纹理数组层和已占笔触槽位。记录分配容量与实际占用、宽高/格式/层数/mipmap、估算字节及引擎可用的实测纹理显存。动态页反复上传按流量计，同一纹理重复更新不会增加存活数。[当前染色与缓存](染色系统.md) |

低频同步采进程驻留内存、引擎静态内存、对象/资源/节点/孤儿节点数、显存及纹理内存。各值保存单位、采样时间、平台和可用性。驱动缓存、分配器保留页和共享显存可能重叠，分别画趋势。自然获得的伙伴、当图永久留色和进程共享图集分别对照各自预期寿命。

每次换图在旧图退出前、新图构建后、延迟销毁经帧末处理后，以及新图相同阶段的稳定窗口留样。新局重复同样检查。按旧代次核对“期初存活 + 新建 − 实际释放 = 期末存活”。对仍存活项列所有者、资源键、最后一次创建/借用位置及预期释放点；用弱引用或登记表抽查旧石碑材质、特效节点和动态页是否仍可达。保留跨图共享资产的理由。[换图清理边界](../../src/game/full_game/level_system.gd) · [已有材质弱引用回归](../../src/game/full_game/performance_test.gd)

若同负载重复进出后旧代次存活基线阶梯式抬升，列为疑似泄漏；找到持有者并证明超出预期寿命，才确认对应残留。若数量回落但每帧新建、释放或上传率居高，同时出现慢帧，检查分配抖动和上传；若仅内存水位升高而对象稳定，先核对缓存容量、引擎与进程指标。单张快照或三关末尾的显存差不足以判定泄漏。

## 输出与验收

- 每次运行独立保存版本/工作区源文件哈希、设备、引擎和渲染后端、分辨率、帧率上限/垂直同步、特效档、种子、输入及采样模式。记录初始缓存状态、节点/奖励选择、队伍构成、敌人数与染色量。保留原始观测、里程碑与摘要，过程文件归入 `_local/`，可复核结果归入性能评审目录。
- 每帧用固定容量缓冲保留帧间隔及分项计时；资源水位建议每秒采一次，换图追加快照。分批落盘，记录采集/写盘耗时、缓冲丢样和时钟断点，不在热路径遍历整树、强制 GPU 同步或逐事件打印。普通游玩默认关闭；同设备同路线轮换关闭/开启采样，以共同的外部帧间隔观测估计扰动。
- 报告按星球、节点、阶段和固定真实时间窗（建议 30 秒）输出帧数、P50/P95/P99、最大帧耗、超过目标帧预算的比例与最长连续超预算帧数。预算按该设备测试目标换算，如 60 FPS 为 16.67 ms，30 FPS 为 33.33 ms。保留最慢帧前后时序、CPU 自身耗时排名、GPU 有效样本数、当时资源数及其增减；图上对齐换图、慢帧和旧代次存活曲线。
- 第一轮先核对埋点自身：范围嵌套/提前返回、多物理步、共享图集、池归还、延迟销毁、GPU 缺测和缓冲溢出均有可观察结果。第二轮在实际渲染窗口完成自然路线，建议同版本同种子至少三次，逐轮比较同阶段、相近队伍/敌人/可见负载的窗口，同时保留未经匹配的真实增长。headless 仅验逻辑及计数；目标手机的帧耗与内存结论需要对应真机样本。
- 判读分别给出首次持续退化窗口、超预算时间的主要已测来源、尚未解释的部分，以及旧代次回收结果。对可疑项只改一个因素复测，并核对战斗/染色结果和输入路线。修复后用同版本条件与原问题路线复跑。未抵达第三关、缺少有效 GPU 数据或无法重现时，写明哪些判断仍待取证。
