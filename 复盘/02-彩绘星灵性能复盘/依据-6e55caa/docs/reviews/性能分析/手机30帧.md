# 手机网页 30 帧候选（已放弃）

2026-11-20 状态为 superseded。A／B／C 保留为沙盒历史样本，当时未获手机实测。正式版恢复默认 60 Hz 物理步，与移动同步推进规则。[当前架构](../../architecture/主游戏代码架构.md#一次物理步)

当时的目标是在 15 伙伴、30 敌人的标准场景中维持整帧 P95 ≤ 33 ms，并保留桌面的逐绘制帧插值。候选从 `e6addbbe899d16a84e07822d737fe72e4d760290` 加当时工作区改动建立。当时的正式工程使用 16 Hz 规则步。测试包和证据保存在本机，三包的操作步骤见[真机测试说明](../../../_local/性能优化/手机30帧/真机测试说明.md)。

## 集成回归与桌面帧耗

C 与修正后的 30 Hz 基线通过同一组 47 项快速回归。排除辅助夹具后，全量 79 项均与 16 Hz 起点同状态，48 项通过、17 项已有失败、14 项已有超时。方案点名的四个失败脚本错误集合一致。C 与 30 Hz 基线的八帧 GPU 截图逐像素一致。三个 Web 包均通过资源清单、ZIP 和 PCK 检查；Windows Chrome 已逐包用触屏事件启动压力场景并下载完整 60 秒 JSON。

固定两个逻辑 CPU，串行三轮，每轮 1,800 个绘制帧。带规则步的物理回调均值中位数从 11.25 降至 10.71 ms，P95 从 21.55 降至 20.61 ms。无窗口整帧间隔 P95 从 21.51 降至 20.84 ms。C 的单步最高观测为 108.85 ms；P95 与均值的比值为 1.92。三轮有波动，手机单步预算须由机型标定。阶段 3 的错相、分片与画质选项均未启用。
